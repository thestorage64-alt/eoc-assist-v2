## Rendering model

- **Server components** read data by importing the module functions directly
  (`@/lib/insight/dashboard`, `@/lib/circulars/repo`, …). Do not fetch your own API from a
  server component.
- **Client components** only for interaction (forms, buttons, optimistic state) and call
  `/api/*` via `src/lib/client/api.ts`.
- Every authenticated page starts with `resolveActor`; no actor ⇒ `redirect("/login")`.

## Design system — `globals.css`

Port the tokens from two places, deliberately:

From the **pitch design** (`E:\GEARS Presentation project\showcase\index.html`): navy rail
`#0d1f3c`, blue `#0e6db3`, crimson `#c8232b`, marigold `#f2c14e`, 14px cards, the 5px
tricolour top rule, 18px card padding.

From the **inherited app** (`EOC-Assist-App/.../app/globals.css`): the semantic token
approach, `:focus-visible` ring, `prefers-reduced-motion`, light/dark palettes, radius scale.

Required tokens (light + dark):
`--bg --panel --text --muted --line --accent --accent-2 --gold --danger --ok --warn
--r-card --r-control --shadow --focus`

Type scale: 34 / 26 / 20 / 16 / 14. Spacing rhythm: 4 / 8 / 12 / 16 / 24 / 32.
No Tailwind. No CSS-in-JS library.

## Accessibility — non-negotiable (these were failures in the prototype)

- Semantic landmarks: `<nav> <main> <header>`, one `<h1>` per page.
- `aria-current="page"` on the active nav item.
- Visible `:focus-visible` ring on every interactive element.
- Every form control has a `<label>`; every icon-only button has `aria-label`.
- Decorative SVGs get `aria-hidden="true"`.
- Skip link to `#main` as the first focusable element.
- `prefers-reduced-motion: reduce` disables transitions.
- Text contrast ≥ 4.5:1 for body, ≥ 3:1 for large text. Check muted-on-panel explicitly.
- **No fixed `100vh` + `overflow:hidden`.** The app must scroll and work at 375px.
- Tables scroll horizontally on mobile instead of clipping.

## Screens

**Login** — split layout; email + password; inline error; no account enumeration ("Invalid
email or password"). On success go to `/command`.

**Shell** — navy rail (desktop), mobile drawer with Escape + backdrop + focus trap, topbar with
current page name, signed-in user and sign-out. Nav items are filtered by capability: a member
sees fewer items than the chair; the principal sees everything read-only.

**Command centre** — role-shaped: "Needs your attention" list, four KPIs, cell load bars,
deadline radar. Principal sees the institution; head sees their cells; member sees their work.
Empty states name the next action, never a blank box.

**Circulars** — filter by state and cell, search by title/body; table with ref, title, cell,
state, due, owner. `+ New circular` opens the composer.

**Circular detail** — the most important screen:
source text on the left, right rail with classification panel, then meetings, actions,
documents, timeline. Actions visible by permission: Suggest (not principal), Confirm/Correct
(chair/head only), Advance stage (chair/head), Add meeting, Export.
The classification panel must **label the suggestion as a suggestion** and show the human
decision separately, including who decided and when.

**Workflow** — nine columns, every column rendered even when empty, count in the header,
cards with title/cell/due/owner. Horizontal scroll. No drag-and-drop requirement.

**Cells** — 14 cards: number, name, head, open count, next due. Clicking opens a filtered
circular list.

**Reports** — period selector, totals, per-cell table, SDG coverage, "Download evidence pack".

## Empty, loading, error

- Skeleton for async panels (no layout shift).
- Error state is inline and actionable ("Couldn't load circulars — retry"), never a blank page.
- If AI is not configured, the panel says so and offers manual classification. Never a fake
  suggestion.
